## 2. 键盘可玩性（手感返工新增）

`src/debug/drift-bot.ts` 是一个只会按键盘的驾驶机器人：转向只有 −1 / 0 / +1，踏板只有开和关，漂移中每 0.09 秒重新决定一次。它用的就是游戏教的手法（减到入弯车速 → 按住方向点空格 → 按住收紧、松开放宽 → 提前松手出弯）。

测试 `playability: a keyboard-style driver on the real circuit` 的结果：

| 项 | 结果 |
| --- | --- |
| 连跑 3 圈 | 完成，圈速 66.7 / 64.0 / 64.1 s |
| 碰墙 | 0 次撞车，0 步贴墙 |
| 每个漂移弯里保持漂移的时间占比 | 全部 > 90% |
| 全程漂移时间占比 | 57% |
| 连击 | 爬坡 S 弯连出 ×2 |
| 3 圈总分 | 5776 |

不同配置的对比（3 圈，同一个最终版机器人）：

| 配置 | 撞车次数 | 最高倍率 | 总分 |
| --- | --- | --- | --- |
| 参考赛道 + 参考车 | 6 | ×2 | 4012 |
| 第一版赛道（路宽 16 m、12 弯）+ 第一版车 | 0 | ×4 | 14088 |
| 现在的赛道 + 现在的车 | 0 | ×2 | 5776 |

第一版赛道用正确手法同样不撞，说明第一版手感差的主因是游戏没把手法和入弯车速告诉玩家，而不是赛道开不过去。详见 `docs/design/drift-gameplay.md` 第 2.5 节。

## 4. 性能

生产构建（`npm run build` 后 `npx vite preview`），WebGPU，1920×1080，漂移演示跑两圈，逐帧采样 15291 帧：

| 项 | 值 |
| --- | --- |
| 平均帧时间 | 8.34 ms（屏幕 120 Hz，被刷新率封顶） |
| P95 / P99 / 最大 | 9.2 / 9.4 / 32.5 ms |
| Draw call | 98–169 |
| 游戏主包 | 1397 KB（gzip 372 KB）；入口 3 KB |
| 车模 | 2.35 MB，20 个 mesh（含车底阴影片） |

测试机是 Apple M5，比验收目标（Apple M1 级 60 fps）快，M1 级机器上的帧率没有测。开发服务器用的是引擎调试构建，帧率比生产构建低，量性能要用生产构建。

## 5. 实现时发现并修掉的问题

| 问题 | 处理 |
| --- | --- |
| 车斜着撞墙时车头穿进墙里（只按车中心判定） | 护墙判定按车身朝向算伸出量；返工时把这部分伸出量减半，免得漂移可用路宽太窄 |
| 追车相机会穿到护墙外面 | 相机横向位置钳在护墙内侧 0.7 m |
| 车在阴影里像浮着 | 加车底模糊阴影片 |
| 车轮压上路肩时陷进去 | 按四个轮子压到的路肩高度抬起并倾斜车身 |
| 漂移时仪表速度偏低约 30% | 仪表改显示实际行驶速度（原来是车头方向的分量） |
| 演示和自动驾驶跑出的圈速被存成最佳圈速 | 有机器人参与的圈不计入最佳成绩 |

## 6. 已知不足

- 没有音效：轮胎啸叫和引擎声对漂移手感影响很大，排在 M3。
- 地形是临时的平滑山体，发卡弯内侧有一道接缝；M2 换成噪声高度图和湖。
- 天空是程序化渐变加云，没有后处理；M2 做。
- 近处沥青贴图偏糊。
