# M2 验收记录（2026-11-25）

> 结论：M2「像参考作品一样好看」的三条验收都已运行验证：氮气规则单测通过，固定机位截图已和参考帧并排对比，Normal 档整圈帧时间和 draw call 已记录。没验证的有：真人试玩、Apple M1 级机器上的帧率、Low / High / Ultra 三档画质的实际效果。

## 2. 浏览器实测

环境：Chrome（独立实例，1920×1080 画布），Apple M5，Normal 档。

| 检查 | 结果 |
| --- | --- |
| WebGPU：动态天空、体积云、太阳光晕、阴影、后处理、湿路反射、镜头效果、全部特效 | 首次接入即无控制台报错 |
| WebGL2（`?device=webgl2`）：同上 | 无控制台报错 |
| 氮气：按住 N 喷射，尾焰、镜头拉宽、速度线 | 正常；尾焰会映在湿路面上。边缘色散没有单独确认 |
| 拾取碎片：青色六角晶体 | 晶体显示正常；拾取、加罐、重生由单测覆盖，没有在画面里专门看过拾取动画 |
| 湿路面：平面反射能映出车身、天空、霓虹；雨滴涟漪 | 反射和涟漪都可见；涟漪的循环动画没有逐帧核对 |
| 防雪走廊：拱窗透光、霓虹灯带 | 正常。走廊内的车灯光束只跑过无渲染检查，画面里没有单独确认 |
| 擦墙火花 | 贴墙滑行时在车与墙之间出现 |
| 广告板文字、`>>` 指示牌方向 | 文字不反，箭头指向弯内 |
| 演示机器人整圈 | 生产构建下 66.72 s，不贴墙，连击 ×2 |

实测中改掉的问题：

| 问题 | 处理 |
| --- | --- |
| 后轮水雾太白太浓，像一团雾 | 颜色压暗、不透明度从 0.3 降到 0.14、尺寸缩小 |
| 雨滴涟漪的圆环有半米多宽，像弹坑 | 平铺加密，圆环缩到约 0.2 m |
| 天空是白天的蓝色 | 太阳仰角 8° → 5°，加大浑浊度和米氏散射，调色偏暖 |
| 湖面近乎黑色，像泥地 | 改成以反射为主的材质，映出天空 |
| 防雪走廊封闭侧墙面过曝发白 | 混凝土颜色压暗，补光强度减半 |
| 镜头水滴太密 | 减少水滴数量 |

## 4. 性能

生产构建，Normal 档，1920×1080，演示机器人驾驶，逐帧采样：

| 项 | WebGPU（整圈，7636 帧） | WebGL2（前 1270 m，2045 帧） |
| --- | --- | --- |
| 平均帧时间 | 8.51 ms（120 Hz 屏幕封顶） | 10.57 ms |
| P95 / P99 | 9.3 / 16.7 ms | 17.1 / 25.1 ms |
| 最长一帧 | 41.7 ms | 383.5 ms |
| Draw call | 338–595，平均 457 | 最高 565 |

- 最长那几帧出现在第一次用到某个效果时（着色器现编），WebGL2 上最明显。着色器预热排在 M3。
- 采样在最后几处调色（湖面、走廊亮度）之前做的，这些改动不影响绘制数量。
- 游戏主包 1742 KB（gzip 466 KB）。
- 测试机是 Apple M5；验收目标是 Apple M1 级机器 60 fps，没有测。

场景规模（Normal 档，由无渲染脚本统计）：地形 30.5 万三角面、40 块；树 369 棵（实例化）；草同时约 1.3–1.4 万丛；道具 14 个渲染实体（9 段广告板、79 块指示牌、68 盏路灯、68 根里程桩、8 组桥墩、防雪走廊）；程序化生成耗时约 0.27 s（预算 2.5 s）。

## 5. 没做或没验证的

- **着色器预热**：没有，首次喷氮气、首次擦墙会卡一下。M3 做。
- **草和树的风摆**：没有，都是静止的。
- **走廊里的体积光束**：没接。
- **太阳光晕被山体遮挡**：换成正式地形后没有专门核对过。
- **Low / High / Ultra 画质档**：配置表已接入各模块，但只实际看过 Normal 档。
- **真人试玩**：氮气手感、碎片位置是否顺手，都没有人试过。演示机器人走内线，一圈一个碎片都吃不到。
