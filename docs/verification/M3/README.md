# M3 验收记录（2026-11-26）

> 结论：M3「可发布」的功能都已做完并运行验证：程序化音频、菜单/加载/暂停/致谢、手柄与触屏、画质档菜单、着色器预热、静态托管；附加任务「优化性能和内存占用」也已完成并有前后对比。三条验收里，「键盘、手柄、触屏各跑一整圈」和「生产构建在静态托管上能跑」已验证；「引擎声平滑无爆音」只有波形检查，没有人听过；「Low 档在中端手机可玩」只在手机视口的桌面浏览器里验过，没有上真机。

命令 `npm test`，结果 **142 条全过**（7 个文件）；`npx tsc --noEmit` 无报错。相对 M2 新增：

## 2. 三种输入各跑一整圈

做法：调试句柄新增 `__game.coDrive(fn)`。手动模式下，漂移机器人每个模拟步报出"它想按什么"，页面里的测试脚本把它变成真实的设备事件，车仍然只由设备读到的输入驱动。这样每种设备的整条代码路径（事件 → 读取 → 合并 → 模拟）都跑了一整圈。

| 设备 | 事件来源 | 圈速 | 碰墙步数 | 漂移次数 / 最高连击 |
| --- | --- | --- | --- | --- |
| 键盘 | 合成的 `keydown` / `keyup`（W A S D 空格 N） | 1:06.725 | 0 | 10 / ×2 |
| 手柄 | 替换 `navigator.getGamepads` 的标准映射手柄（左摇杆、RT、LT、X、A） | 1:06.950 | 0 | 10 / ×2 |
| 触屏 | 合成的 `pointerType: 'touch'` 指针事件：左半屏拖动转向，点漂移、刹车、氮气按钮；844×390、像素比 3、Low 档 | 1:06.650 | 0 | 9 / ×2 |

没验证的：真实手柄硬件、真实手机上的手指操作，以及真人用这三种设备的手感。

## 4. 性能与内存优化（附加任务）

### 4.1 前后对比

「之前」是 M2 结束时的数字（1920×1080，当时代码里把像素比硬乘了 1.5）。「之后」的画布是 1280×720（Normal 档像素比上限 1）。

| 项 | 之前 | 之后 | 之后是怎么测的 |
| --- | --- | --- | --- |
| 加载到可开车 | 3.08 s | 2.06–2.16 s（其中预热 0.75–0.98 s） | 有界面 Chrome，WebGL2 和 WebGPU 各一次 |
| 纹理显存 | 125.4 MB | 65.8–72.4 MB | `device._vram.tex` |
| 顶点 / 索引缓冲 | 11.5 / 2.5 MB | 11.0 / 2.4 MB | 同上 |
| JS 堆 | 45.5–70.5 MB | WebGPU 21.4–64.8 MB，WebGL2 14.9–48.0 MB | 无界面 Chrome 整圈，`Runtime.getHeapUsage` 每秒一次 |
| 每帧垃圾（WebGL2，60 Hz） | 142 KB/帧（8.9 MB/s） | 86 KB/帧（5.6 MB/s） | CDP 分配采样器，10 s |
| 小 GC | 20 s 里 11 次，最长 14.1 ms | 70 s 里 13 次，最长 4.2 ms | CDP trace，优化前后各一次 |
| 整圈平均帧时间（120 Hz 屏） | 8.51 ms | 8.44 ms | 有界面 Chrome，8974 帧 |
| P95 / P99（120 Hz 屏） | 9.3 / 16.7 ms | 9.2 / 9.4 ms | 同上 |
| 整圈超过 20 ms 的帧 | WebGPU 最长 41.7 ms；WebGL2 最长 383.5 ms | WebGPU 1 帧（50 ms）；WebGL2 6 帧（都是 33 ms） | 无界面 Chrome，60 Hz，不开 trace |
| Draw call | 338–595，平均 457 | 313–599，平均 440 | 无界面 Chrome 整圈 |
| 首次喷氮气 / 擦墙的卡顿 | 41–383 ms | 约 25 ms | 上一轮在有界面 Chrome 里测的 |

这张表有三处要当心：

- 120 Hz 那组帧时间（8974 帧）采样期间，测试窗口里有人在用键盘开车，采样里最长一帧 166 ms、超过 20 ms 的有 17 帧，原因没法区分，所以没有写进表里的"最长一帧"。采样时车尾小零件还在投影（那项优化是之后做的）。
- 无界面 Chrome 固定 60 Hz，它的帧时间只能看"有没有掉帧"，不能和 120 Hz 的平均值比。
- 开着 CDP trace 时会出现 100 ms 和 650 ms 的单帧，关掉 trace 重测就没有，是 trace 本身造成的。

### 4.2 做了什么

| 改动 | 位置 | 效果 |
| --- | --- | --- |
| 去掉像素比硬乘 1.5，改由画质档决定 | `src/game.ts`、`src/config/quality.ts` | 渲染像素数降到原来的 44% |
| 贴图尺寸：路面漫反射 2048 → 1024，涟漪 24 帧 256² → 16 帧 128²，光晕 512 → 256 | `src/config/wet-road.ts`、`src/config/post.ts` | 纹理显存减少约 50 MB |
| 上传到 GPU 后释放网格的 CPU 侧数据和贴图的源数据 | `src/core/memory.ts` | JS 堆下降 |
| 近处地形移到 Road 图层，不进路面反射 | `src/world/terrain.ts` | 反射相机少画 Draw call |
| Normal 档关体积雾；自动曝光改成按隧道系数直接算 | `src/config/quality.ts`、`src/render/post.ts` | 少两个全屏通道 |
| 着色器预热：加载末尾渲染 12 帧，特效全开，期间所有相机关闭视锥剔除 | `src/game.ts` | 整圈不再现编着色器 |
| HUD 刷新降到 30 Hz；`frameAt` / `project` 不再分配对象 | `src/game.ts`、`src/track/track.ts` | 每帧垃圾减少 |
| 雨滴涟漪换帧时直接改材质的贴图参数，不调 `material.update()`；湖面涟漪每秒只推 20 次 | `src/world/wet-road.ts`、`src/world/world.ts` | 每帧垃圾减少 |
| 每步都跑的代码里 `Math.hypot` 换成 `Math.sqrt` | `src/vehicle/car.ts` 等 | 每帧垃圾减少；回放和可玩性测试结果不变 |
| 车灯、车标、镀铬件不投影 | `src/config/vfx.ts`、`src/render/car-visual.ts` | 每个级联、每个相机少 5 个 Draw call |

### 4.3 查错了一次

中途我用 `performance.memory` 的差值得出"第二个阴影级联是垃圾的主要来源"。这个结论是错的：换用 CDP 分配采样器按函数归因后，级联数量对稳态垃圾没有影响；那次"下降"的读数不可靠。真正的来源是预热漏掉的着色器变体（单次编译产生约 16 MB 垃圾）、草地瓦片填充、每帧的 `material.update()`，以及模拟步里的小数装箱。Normal 档仍是 2 个级联。

### 4.4 知道但没做的

- **路面反射相机会让阳光阴影再渲染一遍**。引擎按"灯 × 相机"渲染方向光阴影，没有按相机关掉的开关。起点处关掉反射少 142 个 Draw call，其中一部分是这遍多出来的阴影。绕开它要给所有被反射的物体加一个不带阴影的镜像图层，走廊里的反射会因此变亮，没有做。
- **剩下的每帧垃圾**（约 86 KB/帧）里，草地瓦片填充约 12 KB，其余大多在引擎内部（阴影视锥、uniform 提交、天空脚本）。
- **游戏主包** 1778 KB（gzip 479 KB），没有再拆。

## 6. 没做或没验证的

- **没有人听过声音**。波形检查只能排除削波和硬跳变，听感（引擎声像不像、过渡顺不顺）需要真人确认。
- **没有上真机**：手机、真实手柄都没试过。Low 档在手机视口下每帧 114–175 个 Draw call、纹理显存 41–48 MB，但中端手机的实际帧率不知道。
- **Apple M1 级机器上的帧率**没有测（实测机是 M5）。
- **自动驾驶和调试句柄没有从发布构建里去掉**（`?autopilot`、P 键、`window.__game` 都还在）。
- **草和树的风摆、走廊体积光束**仍然没有。
- **发布形态**（Claude artifact 还是独立静态站点）和**游戏名与品牌露出**仍待项目负责人决定；现在的 `dist/` 是独立静态站点形态，没有试过打包成 artifact。

## 7. 怎么重跑

测量脚本在 `scripts/verify/`，都是零依赖的 Node 脚本，直接用 CDP 驱动本机的 Chrome（无界面）。先 `npm run build`，再 `npx vite preview --port 4183`。

| 目的 | 命令 |
| --- | --- |
| 某种设备跑一圈（`keys` / `pad` / `touch`） | `node scripts/verify/headless.mjs "http://localhost:4183/?play&nopause" file:scripts/verify/device-lap.js 'window.__drive("pad")' sleep:80000 'JSON.stringify(window.__lap)'` |
| 手机视口 | 在上面的命令前加 `VW=844 VH=390 DPR=3 MOBILE=1` |
| 截图 | 表达式里写 `shot:路径.jpeg` |
| 每帧分配按函数归因 | `node scripts/verify/alloc-profile.mjs "<url>" 10`（要看函数名就用 `npx vite build --minify false --outDir /tmp/x` 的构建） |
| 整圈的 GC、帧时间、堆、Draw call | `node scripts/verify/lap-trace.mjs "<url>" 72`（开着 trace 时单帧最大值不可信） |
| 手柄操作暂停菜单 | `file:scripts/verify/pad-menu.js`，再 `window.__tap(9)`（Start）、`__tap(13)`（下）、`__tap(0)`（A） |
| 抓音频输出找爆音 | `file:scripts/verify/audio-tap.js`，72 秒后读 `window.__tap` |
